y→n

▼ Section 5: Systemic Pattern — select → depends on Changes SDK-wide class of silent failures

This is the single most dangerous pattern in the NCS 2.7.0 → 3.2.2 migration.

When a Kconfig changes from select FOO to depends on FOO:

  • select FOO = "I will force-enable FOO regardless of anything else"
  • depends on FOO = "I require FOO to already be enabled, or I silently disappear"

If FOO was never explicitly set (it was being force-enabled), switching to depends on causes the config to silently vanish from the build with no warning, no error. The feature just stops working.
