MCUboot Kconfig Deep Analysis v61 (NCS 2.7.0) → v64 (NCS 3.2.2) — nRF52840 / custom_board

Executive Summary

16 changed, 324 added, 269 removed configs. Key themes:

  • C Library: minimal_libc → picolibc (IO_MINIMAL strips %02x padding!)
  • Swap Algorithm: SWAP_MOVE → SWAP_OFFSET (new, more efficient)
  • Security: FORTIFY_SOURCE enabled, TLV allow-list, compile-time buffer checks
  • Watchdog: BOOT_WATCHDOG_FEED_NRFX_WDT=y prevents soft-brick during swap
  • Build System: child-image → sysbuild; SIGN_IMAGES removed (now implicit)
  • Crypto: TinyCrypt removed → Oberon PSA + CC310 HW acceleration
  • Hardware: DCDC/pin configs → devicetree; SUIT infrastructure removed
  • Image IDs: New MCUBOOT_*_IMAGE_NUMBER system (all informative, default -1)

1. Changed Configs (16)

CONFIG_MINIMAL_LIBC / CONFIG_PICOLIBC CHANGED
MINIMAL_LIBC=y, PICOLIBC=n → MINIMAL_LIBC=n, PICOLIBC=y
NCS 3.x switched default C library from Zephyr's minimal_libc to picolibc. Picolibc is more standards-compliant but larger. With PICOLIBC_IO_MINIMAL=y, printf loses width/padding: %02x with 0x0A → "a" not "0a". Use bin2hex() for hex encoding.
Defined: zephyr/lib/libc/Kconfig — choice LIBC_IMPLEMENTATION
CRITICAL — printf behavior change, binary size growth
CONFIG_MCUBOOT_BOOTLOADER_MODE_SWAP_WITHOUT_SCRATCH CHANGED
y (swap-move) → n (swap-using-move via sysbuild)
Swap algorithm changed. v2.7.0 used SWAP_WITHOUT_SCRATCH (= swap-move). v3.2.2 uses SWAP_USING_MOVE via sysbuild's SB_CONFIG_MCUBOOT_MODE_SWAP_USING_MOVE=y. New BOOT_PREFER_SWAP_OFFSET=y is set but actual BOOT_SWAP_USING_OFFSET=n — preference doesn't override explicit mode.
CRITICAL — swap mechanism changed, test DFU thoroughly
CONFIG_BOOT_SIGNATURE_KEY_FILE CHANGED
"root-ec-p256.pem" → ".../keys/signing_key.pem"
Signing key path changed from default MCUboot key to project-specific private key. This is a project-level override, not an SDK default change.
HIGH — signing key; ensure file exists at build time
CONFIG_CBPRINTF_LIBC_SUBSTS CHANGED
y → n
With minimal_libc, cbprintf replaced libc printf. With picolibc, its own printf is used natively. Combined with IO_MINIMAL, this changes snprintf/snprintk behavior.
HIGH — tied to picolibc migration
CONFIG_FORTIFY_SOURCE_COMPILE_TIME / CONFIG_FORTIFY_SOURCE_NONE CHANGED
NONE=y, COMPILE_TIME=n → NONE=n, COMPILE_TIME=y
Enables -D_FORTIFY_SOURCE=1 for compile-time buffer overflow detection. Catches unsafe buffer operations at compile time with zero runtime cost. Part of NCS 3.x security hardening.
Defined: zephyr/Kconfig.zephyr — choice FORTIFY_SOURCE
MEDIUM — positive security improvement
CONFIG_NCS_MCUBOOT_IN_BUILD CHANGED
y → n
Read-only helper flag. In v2.7.0 (child-image), this told the app "MCUboot is in the build." In v3.2.2 (sysbuild), MCUboot inclusion is handled by SB_CONFIG_BOOTLOADER_MCUBOOT=y instead.
Defined: nrf/samples/Kconfig:24
MEDIUM — build system change, no functional impact
CONFIG_COMPILER_FREESTANDING CHANGED
y → n
Freestanding mode (-ffreestanding) no longer needed because picolibc provides a full C library. Compiler can now make standard library assumptions → better optimization.
LOW — compiler flag, positive change
CONFIG_THREAD_LOCAL_STORAGE CHANGED
n → y
TLS enabled by default in Zephyr 3.x. Selected by PICOLIBC_USE_TOOLCHAIN. MCUboot is single-threaded and doesn't use TLS — minimal code bloat only.
Selected by: picolibc/Kconfig:24 (PICOLIBC_USE_TOOLCHAIN selects TLS)
LOW — MCUboot doesn't use TLS
CONFIG_PLATFORM_SPECIFIC_INIT CHANGED
y → n
Platform-specific init refactored in Zephyr 3.x. Generic init now handles nRF52840 correctly. MCUboot's own init code is independent of this flag.
LOW — no functional change for MCUboot
CONFIG_SCHED_DUMB / CONFIG_WAITQ_DUMB CHANGED
y / y → n / n (→ SCHED_SIMPLE, WAITQ_SIMPLE)
Scheduler and wait queue algorithm names changed from "dumb" to "simple" in Zephyr 3.x. Same implementation, different name. MCUboot is single-threaded — irrelevant.
NONE — naming change, MCUboot ignores scheduler
CONFIG_SEGGER_RTT_SECTION_NONE CHANGED
y → n (→ SECTION_CUSTOM=".rtt_buff_data")
RTT buffer placement changed from default linker rules to explicit .rtt_buff_data section. Better control over RAM layout.
LOW — improves RTT debug if enabled
CONFIG_BUILD_OUTPUT_META CHANGED
y → n
Build metadata file generation disabled. No runtime impact.
NONE — build artifact only
CONFIG_WFA_QT_DEFAULT_INTERFACE / CONFIG_WFA_QT_THREAD_STACK_SIZE CHANGED
"nordic_wlan0" / 4096 → "wlan0" / 5200
Wi-Fi Alliance test config. Has zero impact on MCUboot — this is application-level Wi-Fi config that leaked into the MCUboot .config via Kconfig defaults.
NONE — not relevant to MCUboot

2. Boot/Swap Mechanism Changes

CONFIG_BOOT_WATCHDOG_FEED_NRFX_WDT=y ADDED
Feeds the nRF watchdog during long swap/erase operations. Prevents soft-brick when swap exceeds watchdog timeout. Essential for nRF52840 with swap-based DFU.
Defined: mcuboot/boot/zephyr/Kconfig:1221 — depends on BOOT_WATCHDOG_FEED
CRITICAL — prevents bricking during DFU
CONFIG_BOOT_PREFER_SWAP_OFFSET=y ADDED
New preferred swap algorithm. Replaces BOOT_PREFER_SWAP_MOVE (removed). Offset-based swapping uses 2 bytes/sector status vs 3 for move-based. Saves ~128 bytes for 128 max sectors. Currently a preference only — actual mode is SB_CONFIG_MCUBOOT_MODE_SWAP_USING_MOVE.
HIGH — new swap algorithm preference
CONFIG_BOOT_PREFER_SWAP_MOVE=y REMOVED
The v2.7.0 preferred swap algorithm. Replaced by BOOT_PREFER_SWAP_OFFSET in v3.2.2. The move-based algorithm is still available but no longer the default preference.
HIGH — replaced by SWAP_OFFSET
CONFIG_BOOT_IMG_HASH_ALG_SHA256=y ADDED
Explicit SHA256 hash algorithm selection for image verification. Previously implicit. Required for ECDSA-P256 signature verification (signs SHA256 of image).
Defined: mcuboot/boot/zephyr/Kconfig — choice BOOT_IMG_HASH_ALG
HIGH — required for signature verification
CONFIG_MCUBOOT_USE_TLV_ALLOW_LIST=y ADDED
Validates unprotected TLVs against a compiled-in allow list. Images with unexpected TLV types are rejected. Security hardening — prevents TLV-based attacks. Default=y, can be disabled to save code size.
Defined: mcuboot/boot/zephyr/Kconfig:1303
MEDIUM — security improvement
CONFIG_MCUBOOT_STORAGE_WITH_ERASE=y ADDED
Enables explicit erase support for flash devices. Depends on FLASH_HAS_EXPLICIT_ERASE. nRF52840 internal flash requires explicit erase before write — this must be enabled.
Defined: mcuboot/boot/zephyr/Kconfig:1363
MEDIUM — required for nRF52840 flash
CONFIG_BOOT_BYPASS_KEY_MATCH=n ADDED
When enabled, bypasses key hash matching during signature verification. Security bypass — must remain disabled (=n) in production ECDSA-P256 builds.
MEDIUM — security; correctly disabled
CONFIG_BOOT_KEYS_REVOCATION=n ADDED
Key rotation/revocation support via TLV counters. Not needed for single-key ECDSA-P256 deployments. Consider enabling if key rotation is planned.
LOW — not needed for single-key setups
CONFIG_BOOT_FIH_PROFILE_DEFAULT_*=n ADDED
Fault Injection Hardening profile defaults (LOW/MEDIUM/HIGH). All disabled — your build uses BOOT_FIH_PROFILE_OFF=y. FIH adds 27+ KB overhead, which is problematic for 48KB MCUboot partition.
LOW — correctly off for 48KB partition
CONFIG_BOOT_FLASH_AREA_HOOKS=n / CONFIG_BOOT_GO_HOOKS=n / CONFIG_FIND_NEXT_SLOT_HOOKS=n ADDED
MCUboot hook extension points for custom flash handling, boot flow, and slot selection. For advanced customization only. Correctly disabled for standard builds.
LOW — extension points, not needed
CONFIG_SIGN_IMAGES=y REMOVED
Explicit image signing toggle removed. In v3.2.2 with sysbuild, signing is automatic when SB_CONFIG_BOOTLOADER_MCUBOOT=y and a signature type/key are configured.
LOW — now implicit in sysbuild

3. C Library Migration (minimal_libc → picolibc)

CONFIG_PICOLIBC_IO_MINIMAL=y ADDED
Selects minimal printf/scanf with limited integer support, no floating point, and NO width/padding support. %02x with 0x0A → "a" not "0a". This is triggered by CBPRINTF_NANO=y via Kconfig dependency chain.
Defined: zephyr/lib/libc/picolibc/Kconfig:59 — depends on CBPRINTF_NANO
CRITICAL — format string behavior change
Picolibc IO options hierarchy (picolibc/Kconfig:31-66)
CONFIG_PICOLIBC_IO_FLOAT=n — Full float+integer printf/scanf
CONFIG_PICOLIBC_IO_LONG_LONG=n — Integer with long long, no float
CONFIG_PICOLIBC_IO_INTEGER=n — Integer (no long long, no float) — use this for %02x support
CONFIG_PICOLIBC_IO_MINIMAL=y — Limited integer only (current)
These are a choice — mutually exclusive. To restore zero-padded hex formatting, set CONFIG_PICOLIBC_IO_INTEGER=y instead.
Removed minimal_libc configs (13 configs)
CONFIG_MINIMAL_LIBC_CALLOC/MALLOC/REALLOCARRAY — Were deprecated wrappers around COMMON_LIBC_* equivalents
CONFIG_MINIMAL_LIBC_MALLOC_ARENA_SIZE=-2 — Deprecated, use COMMON_LIBC_MALLOC_ARENA_SIZE
CONFIG_MINIMAL_LIBC_NON_REENTRANT_FUNCTIONS=y — Enabled rand()/gmtime_r() globals
CONFIG_MINIMAL_LIBC_OPTIMIZE_STRING_FOR_SIZE=y — Size-optimized memcpy/memset (saves ~120 bytes on Cortex-M0+)
CONFIG_MINIMAL_LIBC_TIME=y — Enabled time()/gmtime_r()
CONFIG_MINIMAL_LIBC_RAND=n / STRING_ERROR_TABLE=n / LL_PRINTF=n — Feature toggles
CONFIG_COMMON_LIBC_GMTIME_R=y / STRNLEN=y — Moved to picolibc's own implementations
CONFIG_CBPRINTF_FP_ALWAYS_A=n — cbprintf option, not applicable with picolibc
All removed because picolibc provides these functions natively. No migration action needed.
NONE — automatically handled by picolibc
New common libc / kernel configs (8 configs)
CONFIG_LIBC_ERRNO=y — Use picolibc's errno instead of Zephyr's internal one
CONFIG_CURRENT_THREAD_USE_TLS=y — Store current thread pointer in TLS (avoids syscall if userspace enabled)
CONFIG_KERNEL_INIT_PRIORITY_LIBC=35 — Libc init priority (new in v3.2.2)
CONFIG_LIBC_ALLOW_LESS_THAN_64BIT_TIME=n — Requires 64-bit time_t (Y2038 safety)

LOW — infrastructure for picolibc, no MCUboot impact

4. New MCUBOOT_* Configs

CONFIG_NCS_MCUBOOT_IMG_VALIDATE_ATTEMPT_COUNT=1 ADDED
Number of image validation attempts before declaring an image invalid. With count=1 (default), a single failed validation erases the image. Higher values add retry with wait (ATTEMPT_WAIT_MS=5000) to handle transient flash errors.
Defined: mcuboot/boot/zephyr/Kconfig:1481
MEDIUM — consider increasing for field reliability
CONFIG_MCUBOOT_CLEANUP_RAM=n ADDED
When enabled, zeros all RAM before jumping to application. Depends on CPU_CORTEX_M4 (which nRF52840 is). Security feature to prevent bootloader secrets from leaking to app. Disabled — consider enabling for high-security deployments.
Defined: mcuboot/boot/zephyr/Kconfig:502
MEDIUM — security feature, disabled
CONFIG_MCUBOOT_STORAGE_MINIMAL_SCRAMBLE=n ADDED
Experimental. When removing a bad image, only erases header+footer instead of full slot. Faster but leaves image data in flash. Disabled is correct for production.
Defined: mcuboot/boot/zephyr/Kconfig:1370
LOW — experimental, correctly disabled
CONFIG_MCUBOOT_CHECK_HEADER_LOAD_ADDRESS=n ADDED
Uses image header load address (instead of reset vector) to verify app is in correct slot. Disabled — uses reset vector instead, which is the standard approach for nRF52840.
Defined: mcuboot/boot/zephyr/Kconfig:1448
LOW — alternative slot validation
CONFIG_MCUBOOT_UUID_VID=n / CONFIG_MCUBOOT_UUID_CID=n ADDED
Vendor ID and Class ID verification via image TLVs. Prevents processing images from different vendors/device classes. Not needed for single-product deployments.
Defined: mcuboot/boot/zephyr/Kconfig:1207-1217
LOW — multi-vendor protection, not needed
CONFIG_MCUBOOT_COMPRESSED_IMAGE_SUPPORT_ENABLED=n ADDED
LZMA2 compressed image support. Only works with overwrite-only mode (not swap). Not applicable to your swap-based OTA.
Defined: nrf/sysbuild/Kconfig.mcuboot:99 — depends on MCUBOOT_MODE_OVERWRITE_ONLY
LOW — not compatible with swap mode

5. Security & Build Infrastructure

CONFIG_FLASH_HAS_EXPLICIT_ERASE=y ADDED
New capability flag indicating flash requires explicit erase before reprogramming. nRF52840 internal flash needs this. Enables MCUBOOT_STORAGE_WITH_ERASE which MCUboot uses for swap operations.
Defined: zephyr/drivers/flash/Kconfig:20
MEDIUM — required infrastructure for MCUboot flash ops
CONFIG_CSPRNG_AVAILABLE=y ADDED
Indicates platform has a cryptographically secure PRNG (from zephyr,entropy devicetree chosen). Auto-detected. Replaces old DT_HAS_ZEPHYR_BT_HCI_ENTROPY_ENABLED.
Defined: zephyr/subsys/random/Kconfig:80
MEDIUM — entropy source detection
CONFIG_NRF_SECURITY_ENABLER=y ADDED
Auto-enables NRF_SECURITY (Oberon PSA + CC310 HW crypto) when BT crypto or PSA is needed. Replaces manual mbedTLS/TinyCrypt configuration.
Defined: nrf/Kconfig.nrf:116 — def_bool y, imply NRF_SECURITY
LOW — auto-enabler, works transparently
CONFIG_SB_VALIDATION_STRUCT_HAS_HASH=y / HAS_PUBLIC_KEY=y ADDED
Secure Boot validation structure includes hash and public key fields. Default=y when not using ED25519 pure signatures. Part of Nordic Secure Boot infrastructure.
Defined: nrf/subsys/bootloader/bl_validation/Kconfig:54-64
LOW — Secure Boot metadata structure
CONFIG_DEVICE_DEINIT_SUPPORT=y ADDED
Adds deinit function pointer to every struct device. Enables runtime device teardown. Default=y in v3.2.2. Adds ~4 bytes per device struct — minimal RAM impact for MCUboot's few devices.
Defined: zephyr/kernel/Kconfig.device:36
LOW — small RAM overhead per device
CONFIG_LEGACY_GENERATED_INCLUDE_PATH=y ADDED
Allows old-style #include "version.h" instead of #include <zephyr/version.h>. Backward compatibility shim, default=y.
Defined: zephyr/Kconfig.zephyr:1115
NONE — compatibility shim
CONFIG_FLASH_FILL_BUFFER_SIZE=32 ADDED
Stack-allocated buffer for flash_fill() function. 32 bytes is the default; must respect flash write-block alignment. On nRF52840 (4-byte write block), 32 is fine.
Defined: zephyr/drivers/flash/Kconfig:126
NONE — 32 bytes on stack
