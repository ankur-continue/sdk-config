▼ Section 1: Swap Algorithm & Boot Mechanism 2 CRITICAL, 2 HIGH, 2 MEDIUM
BOOT_PREFER_SWAP_MOVE → BOOT_PREFER_SWAP_OFFSET CRITICAL BOOT SDK DEFAULT CHANGE NEW ALGORITHM
BOOT_PREFER_SWAP_MOVE: default y if SOC_FAMILY_NORDIC_NRF→BOOT_PREFER_SWAP_OFFSET: default y if !scratch && !STM32 (MOVE loses NRF default)
Swap algorithm default changed for Nordic SoCs. In v2.7.0, BOOT_PREFER_SWAP_MOVE had default y if SOC_FAMILY_NORDIC_NRF (Kconfig line 203). In v3.2.2, this default was removed, and depends on !BOOT_PREFER_SWAP_OFFSET was added (line 579). New BOOT_PREFER_SWAP_OFFSET (line 571) defaults to y when no scratch partition is defined. Since the swap-mode choice defaults to BOOT_SWAP_USING_OFFSET if BOOT_PREFER_SWAP_OFFSET, a build without explicit mode setting would get the new offset algorithm.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:203 (v2.7.0) → :571-579 (v3.2.2). BOOT_SWAP_USING_OFFSET: :611-620 (v3.2.2 only).
Current state: Safe — sysbuild forces SB_CONFIG_MCUBOOT_MODE_SWAP_USING_MOVE=y which overrides the preference. Action: Pin CONFIG_BOOT_SWAP_USING_MOVE=y in MCUboot prj.conf as defense-in-depth.
MCUBOOT_BOOTLOADER_MODE_SWAP_WITHOUT_SCRATCH → SWAP_USING_MOVE CRITICAL BOOT
SWAP_WITHOUT_SCRATCH=y→SWAP_USING_MOVE=y
DEPRECATED rename. Same underlying swap algorithm, new Kconfig name. App-side config and any #ifdef referencing old symbol must be updated.
CONFIG_BOOT_PREFER_SWAP_OFFSET=y (new) HIGH BOOT NEW ALGORITHM
not present→y
New swap algorithm preference. swap-using-offset (swap_offset.c, copyright 2025 Nordic) moves sector X+1→X instead of shift-up. Firmware in secondary slot must be at sector+1 offset, not sector 0. Fewer flash writes, faster swap. Currently a preference only — actual mode is BOOT_SWAP_USING_MOVE=y via sysbuild.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:571 (v3.2.2 only). Impl: boot/bootutil/src/swap_offset.c.
BOOT_IMG_HASH_ALG_SHA256=y (new explicit) HIGH BOOT CRYPTO
implicit (SHA256 only)→explicit choice: SHA256/SHA384/SHA512
v3.2.2 introduces formal hash algorithm choice. BOOT_SIGNATURE_TYPE_ECDSA_P256 selects BOOT_IMG_HASH_ALG_SHA256_ALLOW (line 281), which defaults the choice to SHA256. Same outcome as v2.7.0 but now extensible.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:171-218 (v3.2.2). Hidden helper: BOOT_SOMETHING_USES_SHA256 (line 147).
For ECDSA-P256: No behavioral change. SHA256 was hardcoded before, now explicit.

Validates unprotected TLVs against compiled-in allow list. Images with unexpected TLV types rejected. Security hardening. Could reject images if signing tools include non-standard TLVs.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:1303 (v3.2.2 only). default y.
MCUBOOT_STORAGE_WITH_ERASE=y (new) MEDIUM BOOT FLASH

v3.2.2 introduces explicit erase/no-erase support (for RRAM/MRAM devices). On nRF52840 NOR flash, FLASH_HAS_EXPLICIT_ERASE=y auto-selects this. Maps to MCUBOOT_SUPPORT_DEV_WITH_ERASE in mcuboot_config.h.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:1363. depends on FLASH_HAS_EXPLICIT_ERASE, default y.
BOOT_WATCHDOG_FEED_NRFX_WDT=y (new) LOW BOOT HW

Refactored watchdog feeding. v2.7.0 used individual imply NRFX_WDTx with NRFX driver instances. v3.2.2 uses a single BOOT_WATCHDOG_FEED_NRFX_WDT config that accesses WDT hardware registers directly (NRF_WDT0). Functionally equivalent, more reliable.
Kconfig: v2.7.0 :664-673. v3.2.2 :1221-1234.

Auto-calculates max sectors from flash/partition sizes. Defaults to off when Partition Manager is used (your config). BOOT_MAX_IMG_SECTORS=128 continues to work. Would auto-calculate if PM is dropped.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:856 (v3.2.2 only).
CONFIG_SIGN_IMAGES=y (removed) LOW BUILD
y→removed (implicit in sysbuild)
Explicit image signing toggle removed. In v3.2.2 with sysbuild, signing is automatic when signature type/key are configured.
▼ Section 2: C Library Migration (minimal_libc → picolibc) 2 CRITICAL, 1 HIGH
MINIMAL_LIBC=y → PICOLIBC=y + PICOLIBC_IO_MINIMAL=y CRITICAL LIBC
MINIMAL_LIBC=y→PICOLIBC=y, IO_MINIMAL=y
C library changed. NCS 3.x default is picolibc. With PICOLIBC_IO_MINIMAL=y (triggered by CBPRINTF_NANO=y via Kconfig default chain at picolibc/Kconfig:33), printf loses width/padding: %02x with 0x0A → "a" not "0a". MCUboot logs use LOG_INF which goes through picolibc printf.
Kconfig: zephyr/lib/libc/Kconfig choice LIBC_IMPLEMENTATION. picolibc/Kconfig:31-66 IO level hierarchy. Fix: CONFIG_PICOLIBC_IO_INTEGER=y restores formatting.
Impact on MCUboot: Boot logs with hex values (image version, hash fragments, slot info) may show wrong formatting. Not functionally breaking but complicates debugging. Already documented in MEMORY.md as known RCA for BLE pairing failure.
COMMON_LIBC_MALLOC_ARENA_SIZE CRITICAL LIBC SDK DEFAULT 0→-1
implicit 0 (via MINIMAL_LIBC default)→explicit 0 (must be set!)
Libc default change. With MINIMAL_LIBC, the Kconfig had default 0 if MINIMAL_LIBC. With PICOLIBC, that default no longer applies — fallback is -1 (ALL remaining SRAM for malloc). v64 config correctly sets =0. If this explicit setting is ever removed, MCUboot would allocate all remaining RAM to malloc heap in a 48KB partition.
Kconfig: zephyr/lib/libc/common/Kconfig. default 0 if MINIMAL_LIBC — no equivalent default for PICOLIBC.
Action: Pin CONFIG_COMMON_LIBC_MALLOC_ARENA_SIZE=0 in MCUboot prj.conf. Document why.
CBPRINTF_LIBC_SUBSTS HIGH LIBC
y→n
With MINIMAL_LIBC, cbprintf replaced libc printf via imply CBPRINTF_LIBC_SUBSTS if MINIMAL_LIBC (from CBPRINTF_NANO). With picolibc, its own printf is used natively. Combined with IO_MINIMAL, snprintk (which is #define'd to picolibc's snprintf) loses formatting.
Kconfig: zephyr/lib/os/Kconfig.cbprintf:19. Imply chain breaks when MINIMAL_LIBC not used.
COMPILER_FREESTANDING LOW LIBC
y→n
Freestanding mode (-ffreestanding) no longer needed because picolibc provides a full hosted C environment. MINIMAL_LIBC imply COMPILER_FREESTANDING no longer applies.
THREAD_LOCAL_STORAGE LOW LIBC
n→y
TLS enabled by picolibc (PICOLIBC_USE_TOOLCHAIN selects TLS). MCUboot is single-threaded. Minimal code bloat only.
MINIMAL_LIBC_* (13 configs removed) NONE LIBC
CALLOC, MALLOC, REALLOCARRAY, OPTIMIZE_STRING_FOR_SIZE, TIME, etc. All replaced by picolibc's native implementations.
▼ Section 3: Crypto & Security 0 CRITICAL, 1 HIGH, 4 MEDIUM
BOOT_SIGNATURE_KEY_FILE HIGH CRYPTO
"root-ec-p256.pem"→".../keys/signing_key.pem"
Signing key path changed from MCUboot default to project-specific private key. Verify key exists, not in VCS, and matches MCUboot's compiled-in public key hash.
FORTIFY_SOURCE_COMPILE_TIME MEDIUM SECURITY
NONE=y→COMPILE_TIME=y
-D_FORTIFY_SOURCE=1 enabled. Catches unsafe buffer operations at compile time. Zero runtime cost. The Kconfig choice was available in v2.7.0 but defaulted to NONE when MINIMAL_LIBC was used. Picolibc allows it.
Kconfig: zephyr/Kconfig.zephyr:565-595. default FORTIFY_SOURCE_NONE if MINIMAL_LIBC (removed condition).
MCUBOOT_CLEANUP_RAM=n (new) MEDIUM SECURITY
not present→n
New security feature. When enabled, zeros ALL RAM before jumping to application. Prevents bootloader secrets (signature verification intermediates, key material) from being readable by app. Works on Cortex-M4 (nRF52840). Not enabled by default.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:502. depends on CPU_CORTEX_M4 || CPU_CORTEX_M33. Impl: main.c:254-280 — __ramfunc jump_in() zeros RAM before branch.
Consider enabling for defense-in-depth. Adds boot latency (zeroing 256KB RAM). v2.7.0 only had MCUBOOT_NRF_CLEANUP_NONSECURE_RAM for TrustZone devices (not nRF52840).
MBEDTLS_CFG_FILE MEDIUM CRYPTO
"mcuboot-mbedtls-cfg.h" (unconditional)→removed (conditional on TinyCrypt/mbedTLS only)
v2.7.0 unconditionally set this default (line 170). v3.2.2 makes it conditional: only when BOOT_USE_TINYCRYPT or BOOT_USE_MBEDTLS && !MBEDTLS_BUILTIN (lines 536-541). CC310 BL path does NOT use mbedTLS, so this header is no longer included. Crypto path unchanged — CC310 BL library handles ECDSA-P256 directly.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:170 (v2.7.0) → :536-541 (v3.2.2).
BOOT_BYPASS_KEY_MATCH=n (new) MEDIUM SECURITY
not present→n
When enabled, skips TLV key hash matching against compiled-in key. Signature verification still occurs. Minor optimization for single-key setups. Must remain =n in production with multiple key support.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:387. depends on !BOOT_HW_KEY.
BOOT_ECDSA_CC310=y (unchanged) LOW CRYPTO
CC310 BL crypto path is functionally identical in both versions. Same selects: BOOT_USE_NRF_CC310_BL, NRF_CC310_BL, NRFXLIB_CRYPTO, BOOT_USE_CC310. NCS overlay still forces CC310 when HAS_HW_NRF_CC310. v3.2.2 adds BOOT_ECDSA_PSA as alternative (only when NRF_SECURITY=y).
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:107-114 (v2.7.0) → :293-299 (v3.2.2). Identical definition.
BOOT_KEYS_REVOCATION=n (new) LOW SECURITY
KMU-based key rotation/revocation. Only for nRF54L/nRF54H with CRACEN. Not applicable to nRF52840.
Kconfig: bootloader/mcuboot/boot/zephyr/Kconfig:437. depends on BOOT_SIGNATURE_USING_KMU.
NRF_SECURITY_ENABLER=y (new) LOW CRYPTO
App-level auto-enabler for NRF_SECURITY when BT crypto is needed. def_bool y but imply NRF_SECURITY conditions (BT_CRYPTO, etc.) are not met in MCUboot. No effect on MCUboot crypto path.
Kconfig: nrf/Kconfig.nrf:116-122 (v3.2.2 only).
SB_VALIDATION_STRUCT_HAS_HASH/PUBLIC_KEY=y (new) NONE SECURITY
Secure Boot validation struct includes hash and public key. Default=y for ECDSA-P256.
CSPRNG_AVAILABLE=y (new) NONE CRYPTO
Platform has CSPRNG from zephyr,entropy DT chosen. Replaces DT_HAS_ZEPHYR_BT_HCI_ENTROPY_ENABLED.
