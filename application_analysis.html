CONFIG_BT_GATT_DYNAMIC_DB CRITICAL BT PRODUCTION RCA
y→n
Root cause of ATT handle restructure bug reported in production. In v61, MCUMGR_TRANSPORT_BT_DYNAMIC_SVC_REGISTRATION=y force-selected BT_GATT_DYNAMIC_DB=y (via Kconfig select). The SMP DFU service was registered at runtime via bt_gatt_service_register(), placing its ATT handles at the end of the GATT table. In NCS 3.2.2, the Kconfig changed from select BT_GATT_DYNAMIC_DB to depends on BT_GATT_DYNAMIC_DB — since no one explicitly enabled DYNAMIC_DB, the SMP service silently switched to static registration via BT_GATT_SERVICE_DEFINE(). Static services get ATT handles assigned at link time based on section ordering, interleaved with other services — this shifts ATT handles for every GATT characteristic. Bonded peers caching old handles will send requests to wrong characteristics.
Source: zephyr/subsys/mgmt/mcumgr/transport/Kconfig.bluetooth:94-101 (v2.7.0: select) vs :106-113 (v3.2.2: depends on)
Impact: Linked with removal of MCUMGR_TRANSPORT_BT_DYNAMIC_SVC_REGISTRATION. Causes ATT handle table reorganization. Fix: ensure BT_GATT_SERVICE_CHANGED=y is set so the stack sends Service Changed indication after OTA, forcing peers to rediscover handles. Or re-enable BT_GATT_DYNAMIC_DB=y to restore original handle layout.

Max L2CAP TX MTU. 247 = 251 (ACL) - 4 (L2CAP header). Halves TX buffer sizes.
Why: Intentional. Correlated with ACL_RX_SIZE. DFU over SMP/BLE uses smaller packets → ~50% throughput reduction. Significant RAM savings.
CONFIG_BT_LONG_WQ_STACK_SIZE LOW BT
1300→1800
BT long workqueue stack (ECC, GATT caching). PSA crypto backend needs more stack than TinyCrypt.
Why: SDK default rose to 1400 (BT_ECC). 1800 gives safety margin for PSA crypto operations.
CONFIG_BT_MAX_PAIRED LOW BT

Minimum encryption key size (octets). v3.2.2 changed default from 7→16. Prevents KNOB attacks. Devices negotiating <16 byte keys will be rejected.

Why: SDK default change in v3.2.2. Major security hardening. iOS 9+ / Android 6+ support SC. Diagnostic tools using legacy pairing will break.

SMP / DFU Transport (Production RCA)

CONFIG_MCUMGR_TRANSPORT_BT_DYNAMIC_SVC_REGISTRATION=y (removed) CRITICAL BT PRODUCTION RCA
Root cause of ATT handle restructure — confirmed production bug. In NCS 2.7.0 this Kconfig used select BT_GATT_DYNAMIC_DB, forcing the SMP (DFU) GATT service to register dynamically at runtime. ATT handles were appended at the end of the GATT table. In NCS 3.2.2 (Zephyr 3.7+), the Kconfig changed to depends on BT_GATT_DYNAMIC_DB. Since BT_GATT_DYNAMIC_DB was not explicitly enabled, this config silently disappeared. The SMP service fell through to BT_GATT_SERVICE_DEFINE() (static, linker-ordered), which repositioned the SMP service attributes interleaved among other services. This shifted ATT handles for ALL characteristics, breaking bonded peers that cached old handles.
Source: zephyr/subsys/mgmt/mcumgr/transport/Kconfig.bluetooth:94 (v2.7.0: select BT_GATT_DYNAMIC_DB) → :106 (v3.2.2: depends on BT_GATT_DYNAMIC_DB). Service impl: smp_bt.c:376-381
Fix options: (1) Re-enable BT_GATT_DYNAMIC_DB=y + MCUMGR_TRANSPORT_BT_DYNAMIC_SVC_REGISTRATION=y to preserve original handle layout. (2) Keep static registration but ensure BT_GATT_SERVICE_CHANGED=y + BT_GATT_CACHING=y so peers rediscover handles after OTA. (3) Force bond clearing on firmware upgrade.
